## New API 雲端通道中斷根因（2026-09-16）

- New API 主機是 `rpi-minicpm`（`100.104.187.25`），服務 `systemd newapi` 為 active、監聽 port 4000；主機本身沒有故障。
- `journalctl -u newapi` 連續出現上游失敗：
  - `Post "https://opencode.ai/zen/go/v1/chat/completions": dial tcp 172.65.90.21:443: i/o timeout`
  - `Post "https://generativelanguage.googleapis.com/...": dial tcp 172.217.112.4:443: i/o timeout`
  - `channel error (channel #7 / #12, status code: 500)`
- 主機網路實測：預設閘道 `10.11.1.1` ping 正常；`ping 1.1.1.1` 100% 遺失；`https://1.1.1.1` `http=000`；DNS 只回 IPv6。
- 結論：內網正常、外網不通，所有雲端通道逾時。韌體與後端設定無關。
- 影響：`NEWAPI_FALLBACK_URL` 指向的雲端路線目前不可用；主要路線已改為 GB10 本地視覺模型，辨識仍可運作（實測 27.8 秒完成）。
- 待處理：修復 `rpi-minicpm` 對外 IPv4 路由或 DNS，之後雲端 fallback 才會恢復。

## 雲端通道恢復與 fallback 順序（2026-09-16 稍晚）

- `rpi-minicpm` 外網恢復：`ping 1.1.1.1` 24ms、`https://1.1.1.1` 301、`https://generativelanguage.googleapis.com` 404（有回應）。
- New API 雲端模型實測：`gemini-flash` 200 / 25.6 秒（16 tokens）；`gemini-3.8-flash` 仍 ReadTimeout 42.8 秒。

  1. 本地 GB10 `qwen3vl-8b-fp8`

- 注意：裝置 HTTP 服務為單連線，連續快速請求可能被重置（ConnectionReset）；重試即恢復，非故障。
